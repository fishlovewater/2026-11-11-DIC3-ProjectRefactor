### **I. Abstract 摘要 (A–F)**
* **A (Attention Getter 動機與引題)**：氣象預報與空氣品質監測資料為民眾規劃日常活動的重要參考依據，然而政府開放資料平台主要著重於環境數據的查詢與呈現，使用者仍需自行整合不同來源的環境資訊。
* **B (But/However 挑戰與 Research Gap)**：現有服務多為通用型預報，缺乏個人偏好、活動情境與環境風險的整合，且未充分驗證兼顧多源環境資料、個人偏好與可追溯性的 AI 系統；若氣象不確定性未揭露，容易造成使用者誤解或過度信任。
* **C (Cure 解藥/提出新方案)**：提出 **「個人化天氣助理」（Personalized Weather Assistant）AI Agent 系統**，整合氣象與空氣品質資料，針對多站行程提供符合地點、時段、活動情境及個人偏好的行前建議。
* **D (Development 方法設計)**：採用 **混合式架構**：先將行程標準化並進行時空對齊與品質檢查，再由領域知識規則決策引擎產生結構化建議，最後由大型語言模型（LLM）負責需求解析、建議解釋與後續問答。
* **E (Experiments 實驗驗證)**：規劃比較「僅官方數據」、「固定規則+文字模板」與「規則引擎+個人偏好+LLM」三種方法，並針對多站跨鄉鎮、高降雨/高 UV、同 AQI 但不同主要污染物、資料缺漏/過期等情境進行測試。
* **F (Findings 主要結果與預期貢獻)**：預期能降低跨平台查詢與自行整合資訊的負擔，提升行前建議之個人相關性、可理解性、實用性及可追溯性。

### **II. Introduction 導論 (G–L)**
* **G (General 現況)**：氣象與環境監測技術發展成熟，中央氣象署與環境部皆提供氣象與空品（AQI）開放資料，為資訊整合奠定技術基礎。
* **H (However 挑戰)**：取得數據不等於能立即決策；不同使用者對溫濕度與空品的感受不同，且同時考量降雨、溫度、UV 及 AQI 需要切換多個平台（如氣象署各觀測網與空品監測網），增加查詢與判讀負擔。
* **I (In literature 文獻中)**：既有研究涵蓋 Weather Agent 對話查詢、MCP 空品介面、Instructor-Worker LLM 多代理人等，但未依個人耐受度建模；個人化熱舒適研究（PCM-RL）則多限於室內環境。
* **J (Judgement 評論/核心思維與專業爭論)**：
  * **五大核心思維**：1. 以行動與影響為中心 2. 相同環境不同需求 3. 考量不確定性與錯判代價 4. 舒適偏好與健康防護分離 5. 建議必須可追溯並分層驗證。
  * **三大專業爭論與決策**：規則判斷 ↔ LLM 建議（採規則判斷+LLM解釋混合架構）；統一標準 ↔ 個人耐受度（採手動偏好設定+確認機制）；簡明建議 ↔ 保留不確定性（採分層呈現）。
* **K (Keypoint 主要目標與創新貢獻)**：涵蓋 **環境資料整合**、**個人化偏好設定**、**行前建議產生機制** 與 **系統實作與評估** 四大貢獻。
* **L (List the organization 文章結構)**：論文依序安排緒論、相關研究、三大核心問題、Proposed Scheme 系統架構、評估設計與結論。

### **III. Related Work 相關研究 (M–O)**
* **M (Methods 方法分類)**：
  * **AI 技術面**：LLM Agent（Weathernews）、MCP 工具呼叫、多代理人 Instructor-Worker 架構、LLM 推薦代理人（Profile/Memory） 及 WXImpactBench 評測基準。
* **N (New proposed 近年新方法與領域知識)**：

* **O (Organize 整理與比較/4xStable & Research Gap)**：
  * 建立 **文獻摘要表（Article Summary Table）** 彙整各文獻之方法與限制。
  * **Research Gap**：既有文獻尚未看到一套經完整驗證的系統，能同時整合多源天氣與空品資料、依使用者紀錄建立耐受度檔案，並轉化為可追溯的日常行前建議。

### **IV. Proposed Scheme 提出的方法 (P)**
* **PA (Aim 目標)**：把官方數據轉化為「此站、此時段、此使用者應採取什麼準備」的可追溯結論。
* **PB (Based on 背景/資料源)**：中央氣象署開放資料（鄉鎮預報）與環境部資料（即時測站與隔日預報）。
* **PC (Cure/Cause 解法原則)**：資料優先、行程分段、健康與舒適分離、不確定性可見、個人化可控制。
* **PD (Design 架構設計)**：設計 11 個核心模組（UI、行程解析、地點時段標準化、帳號偏好記憶管理、資料取得、時空對齊、規則引擎、建議彙整器、LLM 解釋、結果呈現、行後問卷/偏好更新候選）。
* **PE (Paper element 資料模型)**：定義 `UserProfile`, `ItinerarySegment`, `EnvironmentalSnapshot`, `SegmentDecision`, `FeedbackRecord`, `PreferenceUpdateCandidate` 等結構。
* **PF (Formulation / Foundation 理論公式與領域規則)**：
  * 雨具決策成本模型：當 \\(p \times rL > C\\)（\\(p\\) 為遇雨機率、\\(C\\) 為帶傘成本、\\(L\\) 為淋雨損失、\\(r\\) 為避損比例）時帶傘最具成本效益。
  * 領域規則涵蓋降雨、UV、空品（AQI+主要污染物）、冷熱舒適及資料品質旗標。
* **PG & PH (Graph & How 流程與演算法)**：提供步驟式架構圖、詳細流程圖與 **Algorithm 1 (Personalized Weather Anchor Agent Pseudocode)**。
* **PJ (Jump to an example 範例說明)**：以三站式行程（09:00-12:00 臺中南區步行上課、14:00-17:00 彰化戶外活動、19:00-21:00 臺中南區騎車返家）示範分段獨立判斷。
* **PK (Key points 責任邊界)**：**規則引擎** 負責數值判斷與防護提醒；**LLM** 僅負責需求解析與對話解釋，嚴禁 LLM 自行補造數據或修改判定。
* **PL & PM (Later how & Proof 偏好更新機制)**：透過行後問卷產生「偏好更新候選」，須經使用者確認後才更新 `UserProfile`，避免單次偶發回饋干擾長期偏好。

### **V. Simulation 實驗與結果 (Q–V)**
* **Q (Quality and Quantity 評估指標)**：
  * **正確性**（建議可重現性）、**完整性**（重要提醒遺漏率、限制揭露率）、**個人化**（問卷符合度與有用性）、**可理解性** 與 **系統性**（API 成功率、回應時間）。
* **R (Related method 比較對象)**：
  * Baseline A：僅顯示官方原始數值。
  * Baseline B：固定規則 + 固定文字模板。
  * Proposed：規則引擎 + 個人偏好 + LLM 說明。
* **S (Simulation Setup 測試情境)**：多站跨鄉鎮、高降雨/高 UV、同 AQI 但不同主要污染物、即時與隔日預報切換、資料過期/缺漏/超出預報範圍。
* **T, U, V (Tuning & Verification 驗證無偏見與效能)**：採用分層呈現（行動建議 ➔ 原因 ➔ 原始數據與限制），並驗證防護提醒優先於主觀舒適提醒。

---

### **VI. Conclusion 結論 (W–Z)**
* **W (What proposed 回顧)**：整合中央氣象署與環境部開放資料，建立結合規則引擎與 LLM 的個人化天氣助理 Agent 系統。
* **X (eXcel 方法優勢)**：藉由規則與 LLM 的責任劃分，確保防護建議具備可重現性與可追溯性，並顯著降低使用者資訊整合負擔。
* **Y (Yields 主要成果)**：成功將傳統「環境數據呈現」轉化為符合個人需求的「具體出門行動建議」。
* **Z (Zen 未來工作)**：後續將透過實作與測試驗證偏好更新機制、學習演算法的可行性，並擴充跨區移動路線分析能力。
